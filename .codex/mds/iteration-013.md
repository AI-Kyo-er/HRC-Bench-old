# 第十三轮：分开测量状态报告与动作选择

## 起点与问题

上一回合有实质进展：v12 的 128 次调用及独立审计显示，D5 的八个错误方向全部跟随被拒绝的提议，另有重复 finish 和 D4 提前外层投递。当前起点 `8160b9b`，工作区干净，无活句柄。

这些动作错误不能直接说明模型无法读出有效约定。本轮比较同一公开观察上的状态报告与动作选择，检查错误是否随输出任务变化。状态问答本身会引导注意和计算，不是读取模型已有内部知识的探针，也不是因果识别；不能把两次独立调用当成同一个推理过程。

## 固定设计：64 个观察、128 次调用

复用 v12 全部 64 条 full-history 输入：16 条真实轨迹 × D4/D5 × 正常/反序菜单。保留全部时机、接受/拒绝、初始目标及 seed，不只选择错误案例。

每条观察生成两个独立输入：

1. action-replay：逐字复制 v12 原 messages，再执行一次原动作任务，核对跨运行复现。
2. state-readout：原 user 观察逐字不变，仅替换 system 的输出任务及格式指令，保留全部协议语义。要求严格 JSON，固定字段顺序为 outer_blue_destination、guidance_active、current_blue_destination，不选择动作或附加分析。

状态答案只由 v11 公开历史账本归约：outer 为最后被接受的外层目标；D4 指导仍有效、current 为 neutral；D5 指导无效、current 等于有效 outer。不能读私有 case、未来状态或模型答案，也不给模型归约摘要。菜单保留，不把候选筛选作为帮助。

若原 system 中存在多处输出约束，冻结时记录逐字修改点，确保移除 choice 格式冲突，同时不修改接受/拒绝、child-neutral 和 finish 等规则。状态 JSON 严格校验字段、类型和枚举，格式错误单列，不强转布尔字符串、不自动修复或重试。

字段顺序固定在生成要求中，但 JSON 对象键序不等于状态语义；仅键序不同而键集、类型、枚举正确时，单列顺序遵守情况，不把正确状态判错。重复键、缺失/多余键及非法类型仍按解析/格式错误处理。

同官方本地 14B，BF16/SDPA/greedy/seed0/max96；128 次完成即停止，不因结果改提示。最长输入及显存先实测估算，运行前实时查单卡空闲量，足够才启动，不干扰其他任务。无新增物理、下载或量化/offload；原始产物放数据盘并软链接。

## 评分与解释规则

分别报告三个状态字段与联合准确率，按位置、时机、接受/拒绝、菜单及初始目标分组。动作沿 v12 原评分。逐观察交叉列出状态联合正确/错误与动作推进/不推进的四种组合，不只报告两个边际总分。

64 个 action-replay 与 v12 的原响应、choice、评分逐条核对；不复现时保留差异并检查运行配置，不重跑到一致。v12 full 中四个 D5 错误方向及其 aid 对应案例可作来源关联分析，但本轮不重跑 aid，也不把 aid 的旧错误混作本轮 action-replay 错误。

- 若状态能正确报告而动作仍错误，只说明输出任务改变了行为表现，不能直接证明“模型知道却故意不做”。
- 若拒绝条件下 outer 报告也错误，说明需要继续检查一般接受/拒绝更新能力，不优先归因于嵌套。
- 若 active 正确但 current 仍取外层目标，需区分当前有效目标计算与动作映射；仍不直接推断内部表征。
- 若三字段全对且动作任务也改善，先看跨运行复现，不把重复执行的变化归为新方法收益。

本轮仅为受控诊断，不能替代闭环、结构留出、表达变化和真实伙伴响应。旧 14B 门槛不变，全部旧冻结及失败保持。

## 冻结与评分版本记录

system 实际仅替换三处：首行输出任务、原自主选择物品的任务行、末行 choice 输出格式；其余六条协议语义逐字保留。64 个状态查询的 user 与各自动作输入完全一致。

新增五项定向测试及一次全套 62 项通过，测试句柄 `64816`、冻结 `87604` 已退出。冻结 SHA256 为 `04317bc74eb0b5dae36b089de627408fc6df3d9624d093d4679c5f69cfa418af`。原冻结 parser 把键序也作为严格格式要求；执行者收到上面的键序澄清时已完成冻结，因此保留原评分，另建独立派生语义评分。两者并列归档，主解释使用键序不影响语义的口径；不改原输入/输出、冻结源码或调用次数。该澄清来自测量定义检查，不基于已观察的模型成绩。

最长输入 2,160 token，单卡需求 31,244 MiB；正式模型句柄 `79320` 启动前实时核验 GPU2 空闲 48,494 MiB，使用同官方本地模型单卡 BF16。该句柄真实 exit0，128 条输出全部保存。

## 实际结果

64 个 action-replay 的原 messages、response、choice 和评分全部复现 v12。D4 协议推进 28/32，D5 为 4/32；没有把重复运行计成新的独立证据。

| 状态字段 | D4 正确 | D5 正确 | 合计 |
|---|---:|---:|---:|
| 有效外层 blue 目标 | 32/32 | 29/32 | 61/64 |
| guidance_active | 0/32 | 32/32 | 32/64 |
| 当前 blue 目标 | 32/32 | 0/32 | 32/64 |
| 三字段联合 | 0/32 | 0/32 | 0/64 |

64 次状态输出全部为 guidance_active=false、current_blue_destination=neutral。schema 和键序全部合规，无格式错误；因此冻结严格评分与独立语义评分实际差异为零。主控查看了冻结 state system，其中只有类型/枚举说明，没有包含 false/neutral 具体答案的 JSON 示范；固定回答不能直接归因于复制一个答案示例。

外层目标的三个错误均在 before-child、accepted、初始 right、有效 left 的 D5：seed60 正常/反序及 seed61 反序，状态报告错误保留 right。其中 seed60 正常菜单的动作回答反而正确选择 place_blue_left。拒绝条件下的外层目标字段均正确；这不能与 v12 的动作错误合并成“模型不会理解拒绝”的统一结论。

| 同一观察的两次独立调用 | 数量 |
|---|---:|
| 外层目标报告正确、动作正确推进 | 31 |
| 外层目标报告正确、动作不推进 | 30 |
| 外层目标报告错误、动作正确推进 | 1 |
| 外层目标报告错误、动作不推进 | 2 |

按完整联合状态计算，则没有“状态全对”的案例：联合状态错而动作对 32，二者均错 32。只引用外层目标 61/64 而略去另外两个字段，会夸大状态报告能力。

独立审计真实 exit0，核验全部输入来源、三处 system 修改、user 逐字一致、输出解析、评分/交叉表、动作复现和原错误案例关联。状态答案没有被送入动作调用；旧 aid 错误仅用于关联，不当作本轮动作错误。

最终回执确认：键序澄清后的六项定向测试通过，未重跑全套，不能称全套 63 项通过。模型峰值分配显存 30,395,180,544 bytes，PID30711 与自有 GPU 占用均已释放，无活跃任务句柄。原始产物共 5,461,784 bytes，位于 `/data1/sieniwgroup/sieniw/HRC-Bench/results/state_readout_v13`，由项目软链接访问。实验与审计提交为 `e9caf1c`。

## 研究判断

本轮支持将不同输出任务分开测量，尚不支持“完整状态已知但不会行动”：完整状态问答本身没有通过校准。固定 active/current 回答可能涉及字段语义、物理状态与约定状态混淆，或其他输出任务效应；当前没有实验区分这些解释，不能据此识别内部记忆/规划机制。

同一 14B 在这批模板上的重复失败，已经不足以承担原研究的主要论证。后续应先检查协议/字段读法及另一可运行模型的基础表现，再决定是否推进更广泛的组合测试。不能用更细的同模板错误分类替代真实伙伴响应、一般状态更新对照、表达变化和结构留出；完整研究范围仍见研究证据状态表。
