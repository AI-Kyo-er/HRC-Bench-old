# 第十三轮：分开测量状态报告与动作选择

## 起点与问题

上一回合有实质进展：v12 的 128 次调用及独立审计显示，D5 的八个错误方向全部跟随被拒绝的提议，另有重复 finish 和 D4 提前外层投递。当前起点 `8160b9b`，工作区干净，无活句柄。

这些动作错误不能直接说明模型无法读出有效约定。本轮比较同一公开观察上的状态报告与动作选择，检查错误是否随输出任务变化。状态问答本身会引导注意和计算，不是读取模型已有内部知识的探针，也不是因果识别；不能把两次独立调用当成同一个推理过程。

## 固定设计：64 个观察、128 次调用

复用 v12 全部 64 条 full-history 输入：16 条真实轨迹 × D4/D5 × 正常/反序菜单。保留全部时机、接受/拒绝、初始目标及 seed，不只选择错误案例。

每条观察生成两个独立输入：

1. action-replay：逐字复制 v12 原 messages，再执行一次原动作任务，核对跨运行复现。
2. state-readout：原 user 观察逐字不变，仅替换 system 的输出任务及格式指令，保留全部协议语义。要求严格 JSON，固定字段顺序为 outer_blue_destination、guidance_active、current_blue_destination，不选择动作或附加分析。

状态答案只由 v11 公开历史账本归约：outer 为最后被接受的外层目标；D4 指导仍有效、current 为 neutral；D5 指导无效、current 等于有效 outer。不能读私有 case、未来状态或模型答案，也不给模型归约摘要。菜单保留，不把候选筛选作为帮助。

若原 system 中存在多处输出约束，冻结时记录逐字修改点，确保移除 choice 格式冲突，同时不修改接受/拒绝、child-neutral 和 finish 等规则。状态 JSON 严格校验字段、类型和枚举，格式错误单列，不强转布尔字符串、不自动修复或重试。

同官方本地 14B，BF16/SDPA/greedy/seed0/max96；128 次完成即停止，不因结果改提示。最长输入及显存先实测估算，运行前实时查单卡空闲量，足够才启动，不干扰其他任务。无新增物理、下载或量化/offload；原始产物放数据盘并软链接。

## 评分与解释规则

分别报告三个状态字段与联合准确率，按位置、时机、接受/拒绝、菜单及初始目标分组。动作沿 v12 原评分。逐观察交叉列出状态联合正确/错误与动作推进/不推进的四种组合，不只报告两个边际总分。

64 个 action-replay 与 v12 的原响应、choice、评分逐条核对；不复现时保留差异并检查运行配置，不重跑到一致。v12 full 中四个 D5 错误方向及其 aid 对应案例可作来源关联分析，但本轮不重跑 aid，也不把 aid 的旧错误混作本轮 action-replay 错误。

- 若状态能正确报告而动作仍错误，只说明输出任务改变了行为表现，不能直接证明“模型知道却故意不做”。
- 若拒绝条件下 outer 报告也错误，说明需要继续检查一般接受/拒绝更新能力，不优先归因于嵌套。
- 若 active 正确但 current 仍取外层目标，需区分当前有效目标计算与动作映射；仍不直接推断内部表征。
- 若三字段全对且动作任务也改善，先看跨运行复现，不把重复执行的变化归为新方法收益。

本轮仅为受控诊断，不能替代闭环、结构留出、表达变化和真实伙伴响应。旧 14B 门槛不变，全部旧冻结及失败保持。
