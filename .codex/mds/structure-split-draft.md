# 结构划分草案：开发已暴露的组合与真正待留出项

2026-10-03记录，先于第23轮物理执行及其任何模型调用。本文件不是已冻结测试集，也不宣称已有结构泛化结果。具体生成器、同构检查、操作匹配及样本数量尚待实现；最终测试不得直接使用这里未经物理验证的模板。

## 已暴露范围

v18/19的早期指导更新—响应运输—最终放置，v21的检查期间外层更新与presence离返，以及v23预设的检查义务与最终交付职责合取，全部登记为开发结构。v23的24条参考中，L/R、accept/reject、stay/retain/withdraw、seed只是同族变体，不能事后挑一组称结构留出。v22多轮运输和v23预定恢复控制也是已开发基础能力。

以事件节点和有类型边登记，而不是按scenario名字划分：

| 节点或边 | 最低语义 |
|---|---|
| 提议—回应绑定 | 回应引用具体提议；被拒绝提议不能改变当前义务 |
| 义务作用域 | 子活动完成能关闭其局部义务，不能自动关闭仍有效外层义务 |
| 贡献前提 | 请求被接受、实际物理贡献、观察到贡献分别记录 |
| 暂停/撤销 | 暂停保留承诺，撤销后需新承诺；已有物理进度分别保持 |
| 状态失效 | 旧贡献事件保留，但当前载荷位置/支撑改变可使终端要求不再满足 |

图同构时忽略颜色、左右镜像、seed、措辞和菜单顺序；保留边类型、作用域归属、回应绑定以及依赖路径。不同节点数量的模板不能仅靠padding后被称同结构；相同事件集合也不自动意味着相同结构。

## 可供后续验证的两个留出候选

候选T1：检查交还后，机器人已经开始履行外层职责，此时收到公开职责修订并接受或拒绝。修订作用于尚未结束的外层义务，而不是已经结束的检查；不得重复检查来掩盖作用域错误。相较v23，新增的是交还后正在执行的义务被修订这条依赖，不能只将同一消息从早位置移到晚位置便宣称结构改变。具体实例必须确实已有履责进展，且更新会改变后续有效行为。

候选T2：伙伴已完成一次载荷接回后，公开新约定要求机器人继续处理同一blue。旧接回贡献保留，但当前新义务要求实际再次前送和后续操作。这与v23在检查前人为插入提前返程不同：依赖来自已完成贡献后的公开新义务，而不是固定无效操作。需要控制“多了运输工作”这一替代解释，不能直接拿它与较短v23成功率相减。

这两个候选均不得在后续模型开发阶段反复调提示后仍标最终留出。独立物理参考可用于排除控制器失败，但其完整示例、参考动作及运行历史不得进入被评方法的开发提示/调参；若发生暴露，应移回开发集并另立测试模板。T1/T2本身也不覆盖全部六类结构。

## 主比较先行条件

第23轮完成后，应优先检验可辨识的局部—串接—依赖比较，再扩建新物理模块。具体主比较必须在执行前列出相同基础技能和事件多重集、公开消息及作用域、可解的不同后续、预算、方法输入和预期混淆。仅把更新从检查前挪到检查期间，测得的是顺序/距离一同改变的条件差异，不能命名为纯组合效应。

若不能在当前单blue载体上完成绑定×信息距离的交叉，就明确记录构造失败或剩余混淆，先报告范围有限的系统评测；不得通过增加模型调用或更多seed弥补识别缺口。账本辅助已在v19达到12/12，因此它必须进入新组合比较。若它继续解决全部开发与留出结构，应将结论转向公开状态管理的充分性及适用范围，而不是人为禁用它制造基准难度。

测试集冻结前须审查：模板是否真实新增依赖、是否被开发暴露、物理是否可执行、串接参照是否匹配基础工作、当前状态是否泄漏正确目标、单一合法保守策略的成功及代价。审查结果需对应实际生成器和样本，不能仅凭本文写明要求就声称完成。
