# 第九轮：真实历史检查点上的局部接口与作用域恢复诊断

## 开始状态与问题

上一目标回合有实质进展：v8 完成真实载台投递、机器人接手、六条规则参考及输入/成本审计，结果与研究记录已提交。当前起点 `d954868`，工作区干净，没有待续接的运行或下载。

整体目标仍是持续共同活动中交互结构的组合与演化，尚未证明顶会级贡献。本轮转向已有 v7 物理轨迹上的模型诊断，避免继续只累积规则控制成功。v7 的外层 blue 目标 left/right 在相同物理检查点要求不同首次返回动作，适合检验模型对有效历史约定的恢复；其字符串长度、固定模板和单一作用域结构仍有局限。

## 预定证据边界

1. 复用真实 reference 检查点的规范 messages，不把人工改写历史称为真实 rollout。原始输入、来源轨迹、运行源码与评分依据分别保存校验值。
2. 无辅助完整历史与公开归约辅助必须分开。辅助只能由当前公开历史、物理状态与菜单归约，不能从私有 case、答案、未来日志或未发生反馈读取目标。辅助即使有效，也是额外计算帮助。
3. 在所有五个决策位置诊断局部接口与进度追踪，包括新增 stage/finish。完整 B 的恢复表现属于研究测试，不能先挑选其通过再报告组合效果，也不以新小集覆盖或修改旧 14B 门槛。
4. 每个检查点只采一次冻结的 greedy 输出；不会把模型错误后的下一个参考检查点当作该模型自己产生的状态。这是离线、参考轨迹条件下的诊断，不是闭环成功率。
5. 合法动作、推进当前必要子目标的动作、与参考动作相同必须区分。评分不能仅因模型未复现规则策略的任意顺序而判错；先检查公开协议支持的多解集合再冻结。
6. 按目标、菜单顺序和决策位置报告；模板、left/right 字符差和参考轨迹暴露带来的替代解释继续保留。八条轨迹不等于八个独立结构，也不提供未见组合泛化。
7. 不根据本轮结果调整提示追高分。若直接提供当前约定仍不能正确调用 stage/finish 等接口，先据输出定位接口问题；若两种视图均成功，也如实承认此小集未显示困难。

## 已核定的输入与评分

执行者只读核对了八条 v7 reference：首次 blue 返回前均为第五决策、13 个历史事件、预算 8。历史保留 outer 目标、已接受 child、blue 暂存、实际让行、green 完成、child 结束与 outer 恢复；结束事件不重述 outer blue 目标。物理状态均为 red-left、blue-neutral、green-right，伙伴已经清空。

同 seed、同菜单的左右配对去历史后输入完全相同。官方 tokenizer 实测每对等 token 数，且仅一个 left/right token 替换；seed60 全部 1,950 token，seed61 全部 1,949 token，长度差来自 seed 对应的实际状态表达而不是菜单或答案。user 字符数仍相差 1，不能据此说任意表示长度完全一致，更不能排除词面或固定模板策略。第四/第五决策虽物理相同，预算 9/8、历史事件 10/13，不能宣称两位置为严格匹配的作用域因果对照。

冻结采用 40 个真实检查点 × 完整历史/公开辅助两个视图，共 80 次单决策调用，复用已校验的本地 Qwen2.5-14B-Instruct。公开协议允许的推进集合如下：

| 位置 | 协议允许的推进动作 |
|---|---|
| D1 | stage_blue_neutral，或 place/careful_green_right |
| D2 | yield |
| D3 | place/careful_green_right，或 finish_guidance |
| D4 | finish_guidance |
| D5 | place/careful_blue_外层目标 |

D3 提前 finish 在真实协议中合法，因为没有要求 child 结束前 green 必须完成。不能只以参考策略选择 green 而排除 finish。非推进的合法 yield/request 单列；D2 的 request 合法却不能完成退让。这里描述协议推进可接受性，不声称所有替代动作都已实际执行或必然物理成功。若 D1 总选 green，也不能从可接受率推出 stage 已掌握。

每例 full 直接取实际 messages；aid 只追加由公开历史/当前物理状态归约的目标、scope、完成与剩余、义务/帮助摘要及来源说明，不追加正确 action。固定 greedy、seed0、BF16、SDPA、最多 96 新 token，不自动修复输出，不因错误追加重试。按位置、视图、目标、菜单报告协议推进、合法 no-op、参考动作一致性和错误类别，并报告左右配对两者皆正确/一个正确/均错误以及 full→aid 的配对变化。数字只做小集描述，不把同模板或重复物理种子当作独立结构做显著性推断。

启动前以新输入的实际 token 长度估算 KV 与整体显存，并实时查询 `nvidia-smi`，单卡足够才运行；不自动量化、分卡或 offload。所有新大产物仍放数据盘，旧 v7/v8 与旧模型实验均保持。

## 结果出现前的解释规则

- 若 aid 在必要接口上仍失败，先记录输入/动作理解问题，不能把 full 的差直接归为交互结构困难。
- 若 aid 有效而 full 较差，说明这批固定轨迹中显式归约有帮助；归约同时提供目标、scope 和进度，尚不能单独归因于嵌套记忆。
- 若 full 与 aid 均完成全部诊断，应承认当前小集没有暴露缺口，不为追求失败临时改提示或阈值。
- 即使 D5 两个目标都正确，也仅证明此模板配对上的历史敏感选择。结构留出、长度匹配串接、字面替代表达和真正双向伙伴响应仍未验证。
