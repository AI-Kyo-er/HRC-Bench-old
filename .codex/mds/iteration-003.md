## 1. 为什么需要改变实验

v2 中，完整历史和正确状态摘要均只完成 38/180 个指定步骤；独立接口校准也不能稳定使用简单动作。与此同时，环境指定下一物品、遇无效动作便跳过该步，导致模型没有自主规划与恢复的机会。

因此本轮优先改变两个测量条件：动作语义要明确且可校准；行动后果应来自持续的物理世界。v2 数据、评分和提示原样保留，不将新版本分数包装成同一测试集上的公平提升。

## 2. 执行前验收要求

| 部分 | 应取得的证据 | 仍需限制的解释 |
|---|---|---|
| 公开动作接口 | 无历史干扰时能执行独立操作、协助、让权和拒绝后的替代动作；记录原始模型输出 | 校准通过不等于交互组合能力成立 |
| 可恢复交互 | 无害多余求助产生反馈、消耗预算，策略有机会继续；不能编造未运行的恢复成功率 | 不把通信次数直接称为真人负担 |
| 候选动作边界 | 候选来自公开物理事实与通用能力前提，仍包含可能违反未知有效约定的选择 | 不根据隐藏目标或参考答案过滤候选 |
| 真实物理执行 | 关节运动、末端轨迹、物体运动、接触和动作失败均有记录；只允许初始化时设置初始状态 | 不用物体瞬移、直接写入成功或纯文本反馈冒充执行 |
| 伙伴因果作用 | 至少一种伙伴行为改变实际物理资源或可执行前提，例如占位/释放、支撑物移动、接手操作 | 几何代理不代表真实人类运动分布 |
| 持续任务 | 策略可以选择未完成子任务；后续观察来自先前动作产生的状态 | 固定低层技能不代表端到端 VLA 能力 |
| 低层能力控制 | 先测共享控制器的基础抓放与规则策略可行性，再接入模型 | 操作失败不能直接归因于高层协作失败 |
| 实验可追溯 | 开发与新冻结测试分开；保留版本、seed、配置、轨迹与执行状态 | 当前版本变化同时改变多个因素，不能作单因素因果估计 |

初版至少承载一个跨片段依赖案例及其基础操作参照。嵌套、并发、历史赋义、双向诱发和暂离重返是否覆盖，应逐项根据实现行为说明，不能仅靠场景名称判断。

## 3. 模型与运行边界

复用数据盘上的 Qwen2.5-3B-Instruct 固定权重，不因 v2 的低分就反复重跑同一测试或默改标签。新接口先在新的开发任务上校准；若基础行为仍不稳定，优先定位接口与模型的限制，并保留失败记录。

模型、资产、环境和完整轨迹存放于 `/data1/sieniwgroup/sieniw/HRC-Bench/`，项目通过符号链接访问。任何 GPU 运行前检查当前空闲显存，不沿用上一轮快照。仿真后端的选择依据任务需求和实际可运行性；不修改共享机器的系统驱动或占用其他用户服务。

## 4. 结果判断顺序

1. 若低层控制器不能可靠完成基础任务，先定位物理可行性，不评价模型协作能力。
2. 若直接状态下动作接口仍有明显基础失败，记录模型与接口局限，不以组合任务上的低分建立新能力主张。
3. 若基础控制与接口可用，但连续活动失败，检查失败是否发生在有效约定更新、伙伴资源变化或恢复选择处；保留替代解释。
4. 即使新任务表现良好，也只是这一原型的证据。仍需强模型、操作与信息匹配对照、真正结构留出、多任务及多伙伴，才可支持论文层面的推广。
