# 持续共同活动的研究设计与否证条件

本文件把原始idea转成可逐项验收的研究设计，防止反复增加小原型却始终没有检验核心命题。它是待实施方案，不是已经生成的benchmark或完成的结构划分。当前直接证据以[状态表](research-evidence-status.md)和逐轮记录为准。

## 1. 必须回答的核心问题

在同一共同活动里，指导、伙伴贡献和资源变化是否形成跨片段依赖？在基础操作与输入负担可比较时，局部能力的成绩能否预测这种活动的完成、恢复与实际协调代价？对未用于开发或示例的依赖组合，哪些方法仍然有效？

“交互结构”不是角色标签序列。最小表示需区分三类边：公开信息改变后续目标或行为解释；一方的实际贡献满足另一方动作的执行前提；资源占用或分工变化使既有执行关系失效。时间上先后发生不自动等于存在依赖。任务生成器中的图也不证明模型必须使用这些边：还要排除统一保守策略、当前物理位置和显式目标反馈等捷径。

已知理论概念、新角色名或3D仿真不能独立构成新颖性。拟议贡献只能来自可辨识的评测设计、受控实证与有外部意义的结果；若依赖效应完全由一般状态跟踪解释，应如实缩减机制主张，不能把同一现象改名为HRI特有能力。

## 2. 完整范围与最小任务构造

统一活动暂定桌面整理/装箱，一位伙伴和一台机器人；物品、基础技能、共同进展持续存在。以下各行是构造要求，不代表现有实现已覆盖。

| 结构 | 必须实现的关系变化 | 反事实或对照 | 不能作为替代的简单现象 |
|---|---|---|---|
| 接力转换 | 早期有效指导约束伙伴投递后的机器人接手 | 相同交付物理状态，不同可见历史导致不同有效后续；另有近端直接指导控制 | 只切换role字段，或始终给出当前正确目标 |
| 局部嵌套 | 临时子活动改变局部要求，期间外层约定可更新，交还后恢复仍有效的外层 | 无嵌套的长度匹配串接、旧快照恢复基线、显式公开账本 | 测试专用finish语法本身的困难 |
| 同时叠加 | 指导要求、伙伴生产性贡献和真实资源约束同时影响可行选择 | 相同组成事件顺序执行；允许一切真实安全且达成目标的策略 | 两个互不影响的机械动作普通并行 |
| 历史赋义 | 同一伙伴物理行为在不同公开约定下，对共同活动具有不同后果 | 物理检查点和候选相同，正确后续集合或实际代价不同 | 私有意图不可辨识，或物品位置直接编码答案 |
| 主动关系变化 | 机器人请求后，伙伴依据自身可用性、收到的内容与公开承诺接受、修改或拒绝 | 不请求、拒绝、修改与接受均有后果；伙伴不读取机器人隐藏计划 | 永远接受请求或按固定时间自动配合 |
| 暂离与重返 | 一方明确退出某项贡献，期间另一方保留可继续工作，重返后重新衔接未完成分工 | 进度、分工是否仍有效分别变化；比较重复劳动与遗漏 | 仅将资源busy改成ready并命名为人类重返 |

六类是同一活动的结构操作，不要求每个episode强行包含全部六类。现有v16只满足主动请求的部分机制，不能当作完整双向协商；其busy也不算暂离与重返。

## 3. 三层比较必须共同保留

1. 局部条件：单独呈现每个组成能力及其明确前提，评价指导更新、贡献请求/回应、受限资源处理与接手。旧v4工程gate保持原分母与门槛，不能用新任务重新命名旧结果。新增接口另有预先固定的局部测量。
2. 串接条件：使用相同组成能力和基础操作需求，但尽量让约定在本片段内消费，不要求跨片段保持或合并；控制物品、候选、事件类型与数量、任务预算，报告字符/token及操作时间差异。
3. 依赖条件：让前一片段的约定、贡献或资源后果改变后续正确处理方式。必须由公开信息可解；若存在适用于所有条件的合法保守策略，应测试其完成及实际代价，不通过禁用它制造差异。

闭环中伙伴回应与后续历史由策略实际行为产生，不能承诺整条输入逐字/逐tick相同。严格输入配对只适用于预先指定的实际参考检查点；它提供诊断，不代替自主闭环。指导位置变动也会改变新近程度，不能把匹配长度自动解释为排除全部顺序因素。

另设一般状态更新参照：在保留状态转换、信息量与选择需求的情况下，用非人际事件表达相同更新。它检验解释是否仅需要通用状态管理；无差异并不说明任务无用，但会否定“HRI独有计算机制”的说法。该参照尚未制作，不能从当前纯文本失败反推结果。

## 4. 结构留出的可操作定义

先固定可复用的基础事件/技能和关系算子，再以依赖图模板划分开发、示例与最终测试。物体颜色、左右盘、随机seed、菜单顺序和措辞变化单独划为表面变量，均不算结构留出。

拟分两层：第一层留出已知算子的特定组合，例如“局部子活动期间发生贡献可用性变化，并更新外层分工”；第二层留出更长依赖路径或更深作用域，单独报告外推范围。必须先有组成算子的独立覆盖和同操作负担参照，不能将新增控制器/新物理技能混入结构泛化。具体模板清单、图的等价判定与实例数量在生成前冻结，目前尚无可宣称的留出集。

基础模型的预训练数据不可验证，因此只能称“在本benchmark开发/示例划分中未暴露的结构”，不能声称模型一生未见。规则或通用规划算法可能无需训练，仍允许参加；不得排除简单正确方法来维持任务难度。

## 5. 方法与信息边界

至少保留完整历史模型、由公开事件归约的账本辅助模型、完整公开状态上的规则/规划参考，以及有明确能力限制的局部模块组合。历史截断、状态重置或旧快照基线是诊断性消融，不能将人为破坏系统的失败当作基础模型机制证据。

账本不得读取私有目标、未来伙伴计划、正确下一动作或评分器内部完成标签；它可以显式整理历史中已公开的信息。它是有额外计算帮助的架构，不与原始历史输入混称完全等价难度。原始模型门槛失败不意味着模块化方法应被禁止；但原门槛是否通过仍须原样报告。

真实世界控制器只处理几何/接触/能力授权等可执行条件。安全但违背任务约定的动作应能产生真实后果，再由独立评分器判断目标错误；如有任务语义过滤，必须逐项披露，不能称该系统独立维持了全部约定。完成判断也需说明是谁作出：环境自动停止不能证明机器人知道已经完成。

## 6. 主要结果与成本

主要结果为固定预算下的共同任务完成，并另报首次违约、已完成动作重复、丢失有效分工、对拒绝/退出的错误处理，以及实际物理失败。类别可重叠，应给逐例记录，不强行相加。

实际抓放、伙伴贡献、等待、通信决策和任务完成时刻各自计数。零tick协议动作不代表现实通信零成本。仿真在推理时暂停则须分开报告物理时间与模型推理墙钟，不能合称端到端效率。伙伴支持所需接触与危险接触分开；安全控制器拒绝与真正碰撞也分开。

检查点正确率提供错误定位；它不是闭环成功率。两个seed、左右配对或菜单置换不是大量独立任务样本，不据此作广泛显著性结论。最终统计单位应为预先固定的任务/结构实例，结构层和表面变体层分层报告，避免将同模板复制当作证据规模。

## 7. 会改变研究方向的结果

| 若观察到 | 应作出的判断与后续 |
|---|---|
| 强基线局部能力仍不足 | 不能宣称组合缺口；优先定位接口/基础能力或使用合法的模块化方法，不继续堆同模板失败 |
| 统一保守策略同样成功且无实际代价 | 当前任务不能识别被测依赖，需要修改任务关系或降低该项主张，不能禁止合理策略 |
| 新模型、公开账本或简单规划器解决全部原型 | 承认已有原型不足以构成难度证据；测试结构留出和更真实公开观察，而非人为隐藏必要信息 |
| 依赖与串接差异可由一般状态更新参照解释 | 保留集成可靠性的实证，放弃HRI特有内部机制归因 |
| 仅检查点差异，闭环可无代价恢复 | 不夸大其协作后果；分析为什么恢复抹平局部错误 |
| 闭环代价存在且跨结构/表达保持 | 获得进一步研究的依据，仍需更广任务与真人/真机外部验证 |

当前没有任何一行可以保证得到有利结果。是否具备顶会价值，最终取决于受控差异、结构泛化与有意义后果的完整证据链，而不是完成多少轮工程迭代。用户已安排先仿真、后真机；外部有效性保持为明确未完成项。

## 8. 新颖性边界的文献补充

第十七轮核读HABIT及长交互LLM编排安全基准，进一步限制了“任务图”“伙伴响应”“历史规则保持”和多维评价作为独立贡献的空间。具体已核对内容和来源见[第十七轮文献记录](iteration-017.md#新增相邻工作核查)。本设计的关系算子只是实验组织工具；需要由受控组合差异、结构留出和实际后果支持研究价值，不能把表示方式本身当作新理论。

## 9. 主比较的统计对象与执行前匹配

研究主比较应是同一预设任务实例族中，依赖条件与无跨片段依赖串接条件的自主闭环结果差异。若以成功率表示，可记为 `Δ = mean(Y_dependency - Y_serial)`；同一基础实例的左右、菜单等变体先按预设层级汇总，不能把它们当作彼此独立的新结构样本。这里的Δ仅描述所构造干预的效果，不自动证明某种内部机制或HRI特有计算困难。

匹配应发生在执行前：物品与初始物理状态、所需基础技能、伙伴初始能力/资源分布、事件类型及计划预算、候选与最大决策预算等。模型实际多走的步数、重复请求、错误放置后的恢复和额外等待属于结果，应原样记录；不能为让长度相同而裁掉错误历史、强制跳过动作或事后只保留等长成功轨迹。闭环结束时的token和步数差异可以解释成本，但不能冒充执行前已完全匹配。

局部正确率的乘积可以作为附带描述，不能单凭“整段成绩低于局部乘积”就判定组合缺口：组成步骤的错误相关、执行位置与伙伴反馈均可能不同。主要参照仍需实际运行的串接条件，辅以相同物理检查点的输入诊断。基础控制本身缺失或明显不合格时，结论必须保留该限制。

至少同时报告首次约定违反、预算内最终完成、恢复代价三个结果。第一次选错但随后自行纠正，与一直无法完成，是不同失败类型；环境替它拒绝错误目标后成功，也不能等同于自主保持约定。后续若加入明确完成动作，应分开记录物理目标满足和机器人宣布完成，不用私有评分器自动终止替代后者。

先固定完整条件矩阵、各方法可见信息和主要比较，再生成或观察模型输出。某个条件得分不利时不删条件，某一模式恰好通过时不逐题取两模式最优；模型选择、开发数据与最终结构留出应分别记录。本轮80项基础校准不属于新组合效果的最终检验集。
