基本信息与研究目标

项目为HRC-Bench。研究对象是同一共同活动中交互关系的组合与变化：接力、局部嵌套、同时约束、历史赋义、机器人主动引发变化，以及暂离后的重返。用户确定先以仿真为主，真机验证后续安排。

起点是本地idea.md与Liu等2026年HRIBench论文。本地PDF为11页，不含正文所指全部附录；此前分享对话链接只返回登录页。因此当前工作不是原HRIBench的完整复现，也不能假定已读到分享对话内容。

核心问题逐渐明确为：在基础操作可行、信息与任务难度得到控制时，跨片段依赖是否给持续协作带来额外困难？这种困难能否由普通状态追踪、提示形式或简单调度解释？

当前判断

已经建立有实际抓放、接触、载台运输、检查贡献、公开约定和终止判断的仿真原型。规则参考能完成多个组合条件；较强模型在基础持续任务上已出现可复查的遗漏和提前声明。公开账本是有效且允许参与比较的基线。

目前仍不能宣称已经证明“局部能力强但交互组合泛化弱”，也不能宣称已有足以支持顶会论文的核心实证。主要缺口是严格匹配的组合对照、未见结构、强模型之间的稳健性，以及与普通状态维护任务的区分。当前许多实验属于开发、测量验收或离线诊断。

如何读这些数字

  • 规则参考：程序按公开事实选择动作，证明环境与计划可执行，不代表神经模型会做。
  • 模型单步诊断：给模型某个真实或构造的检查点，只评价一次选择；即使下一检查点正确，也不能当作模型自主完成整段活动。
  • 自主闭环：模型输出实际推进环境，后续输入包含其自身行为后果。
  • 任务成功：终止时满足全部当前义务；全程安全另检查整个运动过程。最终物品到位、动作返回成功都不能覆盖途中碰撞。
  • 审计通过：必须说明检查范围。重建一致不等于安全，符合预期的负例也可能是任务失败。
  • 物理tick：仿真时钟。模型推理时物理暂停，不能把仿真时长称作真实人机团队流畅度。
  • 各轮条件、接口与分母不同，下表不能绘制为同一测试集上的单调性能提升曲线。

正在运行的第26轮：设计、阶段结果与剩余工作

模型是本地Qwen3-14B thinking，使用文本形式的公开历史和物理状态选择动作，不是图像输入策略，也没有进行模型训练。机械臂动作真正推进PyBullet物理仿真；模型推理期间物理暂停。完整任务最多48次决策，局部任务最多12次决策。

典型流程是：请求载台前送blue → 放blue到检查台 → 请求检查并等待实际完成 → 处理目标修改的接受/拒绝 → 整理red、blue、green并让载台返回 → 自主声明结束。合法动作不只这一顺序；简单等待、先做red等策略允许参与比较。

直接条件例如“green放右边”；关系条件例如“green与blue同边”。若后来接受blue改到左边，关系条件下green也应改到左边，可能需要返工；直接条件下green仍保持原目标。拒绝提议则不更新blue。完整64条为初始blue左右×接受/拒绝×same/opposite×更新时机×直接/关系表达×完整历史/账本，共六个二值因素；直接臂的same/opposite只用于离线配对，不作为隐含关系指令输入模型。

局部16条先由规则参考完成真实运输/检查前缀，再由模型接手最后双目标整理；该前缀不是模型自主完成。因此不能简单相减局部和完整成功率，就宣称得到纯组合效应。伙伴确认回应和检查贡献由脚本/物理代理实现，本轮presence保持在场，没有真人参与，也没有把原六类结构全部作为本轮因素。

截至快照，原模型PID253762和等待全量结果的审计监视器PID286338仍存活。16:49的速度测量显示，已完成完整回合平均15.6分钟，最近8条平均18.8分钟；当时外推模型运行还需11–14小时，后续审计与报告暂预留1–3小时。这是估计，不是运行截止时刻或保证。

当前冻结比较包含直接目标/关系目标、完整历史/公开账本、接受/拒绝、更新时机及左右目标。局部16条已经独立审计：安全成功14/16，其中完整历史6/8、账本8/8。两个失败均漏green后声明，分别来自不同表达条件。

前八条完整条件阶段审计为任务0/8、安全5/8；这只是相同初始方向、接受回应、same关系下的两个时机组。失败包括提前声明、实际物理失败与预算耗尽。直接账本after_handoff案例虽然四次抓放没有返回技能失败，全程仍有green与载台接触和非目标物位移；因此“技能无失败”不能替代安全审计。

后续完整阶段报告将补齐：原运行真实退出码、全部80条终态、输入与物理全量审计、完整64条按因素和成对比较、首次错误与恢复、失败类型、成功完成时间与失败终止耗时、冻结与结果校验、最终测试证据和Git提交。不得用少数成功轨迹替换全条件分母。

哪些发现改变了研究路线

  1. 更低的模型分数不自动意味着更好的研究任务。早期3B及若干14B/VL接口连基础控制也失败，因此扩大题量不能支持“局部强、组合弱”。后续转向先验证基本接口和实际执行。
  2. 任务可能有不需要历史的捷径。v6发现位置反推和统一保守策略足以完成，v7改用同物理状态、不同有效历史的配对。后来仍允许简单账本与调度基线，避免人为排除正确方案。
  3. 辅助有效不等于找到了内部机制。v10连只有来源声明的包装都有帮助；v13–14的状态问答本身不可靠。报告只主张可见行为差异。
  4. 真实物理后果不可省略。停车、返工、检查台和移动载台均出现过实际接触；有些轨迹终态正确却不安全。后续采用逐tick接触、载荷支持和非目标保持审计。
  5. 声明与完成必须分开。v18以后允许任何时点声明终止，环境事后检查；v19及v26因此暴露真实遗漏，而不是由私有评分器替模型决定何时结束。
  6. 增加结构组件还不等于证明结构贡献。v21–25逐步连接职责、检查、离返、重装和关系目标，但规则可解、物理可行与模型泛化是不同层面的证据。
