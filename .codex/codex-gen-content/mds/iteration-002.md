## 1. 本轮要得到什么证据

首轮不能区分真实模型的能力，也没有证明 HRI 特异性。本轮运行本地开源模型，使研究判断建立在实际模型输出上。测试范围是持续活动中的自然语言决策层，不能替代具身执行或真人协作评价。

问题：在指导被保留、撤销或局部修正，以及伙伴暂离重返时，模型是否能够维持当前有效约定和已完成进度？若提供正确的当前状态摘要，错误是否减少？

这只是原始交互结构框架中的必要机制切片，不能将整个框架重新定义为长文本记忆问答。持续活动至少需记录多步行动、反馈与进度；闭环伙伴应由实际请求触发响应，而非把完整未来回复预先给模型。

理论来源：[Clark 与 Brennan，1991](https://web.stanford.edu/~clark/1990s/Clark%2C%20H.H.%20_%20Brennan%2C%20S.E.%20_Grounding%20in%20communication_%201991.pdf) 将共同基础的持续更新与共同活动的协调联系起来。[Commitments in Human-Robot Interaction，2019](https://arxiv.org/abs/1909.06561) 已讨论共同目标和共享计划中的承诺管理。因此约定维护是已有理论启发的实验变量，不是本项目首次提出的概念。前者本轮仅核对摘要/首段；后者随后进一步阅读了全文的理论、实施框架与修复章节，仍不代表系统综述。

2019 年论文的 [Implementing Commitment / Repairing 章节](https://arxiv.org/html/1909.06561v2) 将监测、发出信号、识别违背与修复联系起来，并区分导致失败的不同不确定性来源；作者明确该框架当时尚未实现。对本研究的启发是：不能只检查数据库式地存下一条约定，还应观察执行时是否发现依赖已失效，并通过可见交互修复。该理论动机不构成当前模型实验有效性的证据，也不授权我们把预测中的人类动机当作可观察真值。

本实验将 proposed、accepted、revoked 作为明确的操作性状态：未接受的提议不能自动取代有效分工，局部修正不能无故改变其他子任务。此规则是研究中的简化协议，不声称人类所有共同活动都遵循显式确认流程。

## 2. 在结果产生前确定的设计

执行者提出的规模：装箱、餐桌、工具准备三个领域；保留、撤销更新、嵌套修正、暂离重返四种开发结构；额外使用嵌套加重返作为组合留出。正式候选集为三个领域、五种结构、两个目标反事实变体，共 30 个连续 episode，分别在完整历史和 oracle 状态摘要条件运行。实际生成器、提示、数据集与模型版本应由执行者冻结并保存校验值。

执行前修订：检查开发数据时发现需要防止目标翻转与伙伴接受/拒绝绑定，因此将伙伴响应设为独立轴，正式集扩为 `3×5×2×2=60` 个 episode，每种观察条件各运行一次，开发集仍为 12 例。两个目标变体与两个伙伴条件不再相互替代。这是首个模型推理前的设计修正，并非看到结果后扩样。代码和冻结数据已提交 `e871f20`，具体 SHA 与 UTC 时间见 `experiments/language/cases/freeze.json`。三个领域共享生成逻辑，只代表三组词汇场景。

留出仅指本项目开发过程中没有用该组合调整提示；不能证明预训练模型从未见过类似组合，也不能凭零样本测试声称训练后的组合泛化。开发记录与正式输出必须分开，正式结果不可用来反复调整同一个测试集上的提示。

模型拟用 [Qwen2.5-3B-Instruct 官方权重](https://huggingface.co/Qwen/Qwen2.5-3B-Instruct)，作为可运行的初始基线；它不是本研究对当前最先进模型的代表性采样。模型卡列出 3.09B 参数、BF16 和 32,768 上下文。具体 revision、软件版本、推理配置与设备由运行记录保存。

按新增存储规则，权重、缓存和较大环境目录放 `/data1/sieniwgroup/sieniw/` 的适当子目录，项目通过符号链接引用。GPU 在启动前重查显存；不连接其他用户的模型服务，不向外部模型接口发送研究任务。

## 3. 观察、评分与混淆边界

1. 模型输入只来自公开历史、当前观察与动作协议；隐藏生成器标签、未来伙伴响应和参考答案不得进入输入。
2. Oracle 摘要来自独立规则归约，属于状态干预，不是模型免费具备的能力，也不能作为一种方法与完整历史公平排名。
3. 两种输入具有不同长度、冗余和表达形式。观察到差异只能提示状态维护或输入表述是候选原因，不能仅靠此对比确认因果机制。
4. 记录原始 prompt、response、解析失败、模型动作、环境反馈、当前进度和规则参考。无效 JSON 与动作语义错误分开统计，不用人工修复输出后悄悄计分。
5. 有多个可接受动作时用动作集合或状态约束判定，不能以任意单一参考字符串拒绝另一条合理路径。
6. 若一次失败会影响之后的可达性，episode 完成率应使用实际闭环轨迹；不能把各次独立问题正确率称为共同活动成功率。
7. 三个领域可能只共享一个底层生成逻辑。领域数量、结构数量、实例数量与独立任务模板数量分别报告，不用换名实例夸大外部有效性。

## 4. 预先确定的解释规则

| 可能的结果 | 本轮可以怎样解释 | 不能声称什么 |
|---|---|---|
| 两种输入均高完成 | 当前测试对该模型过于容易，需检查任务覆盖和边界 | 已证明持续 HRC 已解决 |
| 完整历史较差、摘要较好 | 状态恢复/上下文呈现值得进一步控制 | 已发现独特社会推理缺陷，或摘要方案公平优胜 |
| 两种输入都差 | 先查动作协议、JSON、参考解与可达性，再判断模型限制 | 立即归因为交互组合 |
| 组合留出比局部结构差 | 候选组合困难；仍需长度、信息和计划复杂度对照 | 已排除任务更长或更复杂的解释 |
| 只有少数对象名/领域触发错误 | 可能是词汇或提示敏感性，应保留负面结果 | 泛化到所有 HRC 活动 |

本轮优先完成真实运行与失败定位，不以增加同模板种子来制造显著性。后续仍需要非社会等价控制、更多强模型、严格结构拆分、具身实现，以及与真人协调成本的联系。

对首轮解释作进一步限定：一个 HRC benchmark 的价值不要求其计算困难只能在人类参与时发生。非社会同构控制用于限制“社会专属缺陷”的主张和发现标签捷径；即使它与人类条件同样困难，若任务构造真实、诊断有增量且预测实际协作后果，仍可能有论文价值。因此不能把“人类标签替换后不变”单独作为否定整个方向的门槛。

## 5. 实现覆盖核验与资源方向

执行者在下载期间审查后确认：环境外部指定当前物品，并维护已完成记录。因此当前实验只检验指定步骤下对有效约定、分工与伙伴响应的处理，不检验模型自主选择下一子任务或防止重复劳动的能力。`nested` 只是在第二物品前注入局部修正，没有实现暂停与恢复子任务栈，不能等同于原始 idea 中完整的嵌套协作结构。上述限制在正式推理前记录，不改变已经冻结的数据来制造难度。

用户已明确后续“先以仿真为主，后续再安排真机”。下一阶段应建立物理状态和执行反馈驱动的持续任务，而非继续仅增加文本模板。至少需要：动作真实改变物体/资源状态；模型可选择尚未完成的子任务；伙伴动作依据公开机器人行为产生；局部纠正后保留其他未完成依赖；暂离重返可改变既有分工。物理可执行性、感知输入和真人代表性仍应分别验证。

仿真承载层候选已查一手资料，但尚未安装或验证：[ManiSkill 安装文档](https://maniskill.readthedocs.io/en/latest/user_guide/getting_started/installation.html) 说明状态仿真与渲染依赖不同，并支持指定资产目录；[Human-Robot Gym 官方实现](https://github.com/TUMcps/human-robot-gym) 提供人类动画和 HRC 环境，但安全控制器与软件版本需单独评估。选择应以能否实现以下实验为准，不能因为某个工具最容易画出机器人就算完成。

拟议的最小具身承载任务是连续桌面整理：三件物品、两个目标容器、共享的接近空间。保留同一物理世界与任务记录；指导更改目的地，伙伴协助形成执行前提，空间干预使当前路径失效。必须允许多个要求同时存在；不能用一个互斥角色标签决定全部行为。

| 下一轮检查 | 最低证据 | 不能替代它的结果 |
|---|---|---|
| 物理执行 | 机器人关节/末端动作、物体位姿、接触和失败反馈轨迹 | 执行动作后直接写入目标成功标志 |
| 持续活动 | 策略自行选择下一动作，已完成/未完成工作影响选择 | 环境逐题指定下一物品 |
| 局部纠正与恢复 | 执行中暂停一个子任务，修正后保留其他有效依赖并继续 | 在下一独立题前添加一句新指令 |
| 双向响应 | 伙伴行为因公开请求、取消或让行动作而改变，含拒绝路径 | 固定时间播放始终配合的轨迹 |
| 控制操作难度 | 策略共享低层控制器，先测单独抓放的可行性与失败分布 | 用操作失败掩盖高层协调是否正确 |
| 可解释的结构比较 | 列明事件、观察、可行动作和参考计划成本的匹配/不匹配项 | 仅声称 episode 数或进展步骤相同 |

这是下一轮设计候选，不是已实现能力。首版可使用共享脚本低层技能来隔离高层组织能力，但必须标明这不测量端到端 VLA 操作能力。人类动画或占位代理也不能代表经过验证的真实人类行为分布。

## 6. 实测记录与当前解释

固定 revision 的 Qwen2.5-3B-Instruct 权重下载正常完成。GPU 3 上的开发集与正式推理均已正常退出（执行者记录的句柄分别为 `44716`、`11216`）。正式集为 60 个实例、两种输入视图，共 120 条 episode 评价和 432 次真实模型调用。结果见 [正式摘要](../../results/language_v2/formal_summary.json)，原始 prompt、response、反馈及版本记录保存在对应的数据盘目录。

| 正式条件 | 完整 episode 完成 | 指定物品步骤完成 |
|---|---:|---:|
| 完整历史 | 0/60 | 38/180 |
| Oracle 当前状态摘要 | 3/60 | 38/180 |

两种输入均无 JSON 解析错误。这里的 episode 与步骤是冻结协议下的结果，不是真实具身成功率。相同的步骤完成总数也不表示两种输入在每个配对实例上完全相同。

开发集已出现：模型对不需要支撑的物品输出 `request`，以及在已有明确约定时选择错误目的地。冻结协议在首个无效动作后结束当前物品步骤，不提供恢复机会。尤其“不适用的求助”可能属于额外协调负担或接口理解问题，这种严格终止规则会把它放大成任务失败；不能将低分直接归因于交互结构。

目前结果不支持“提供正确状态摘要足以解决主要错误”，也不能验证“局部交互能力强但组合后变弱”：本轮没有真正的 isolated 基线和语言长度匹配串接条件，且当前模型在简单条件也失败。全历史与摘要对照含表达形式及长度差异，不作因果效果估计。

据此新增一组明确标为**事后接口校准**的独立小测试：三个词汇场景，分别给出直接有效状态下的独立放置、已接受支撑的放置、让权、拒绝后独立放置，沿用同一系统提示和模型，不改写正式集、正式评分或正式分母。其用途是检查基础动作协议是否可用，不属于冻结主实验或结构留出证据。

接口校准已正常退出（句柄 `62118`）：有效动作 6/12，能立即完成当前物品的动作 3/12，无解析错误或生成截断，见 [校准摘要](../../results/language_v2/calibration_summary.json)。已接受支撑的三例均正确；独立放置和让权各三例均错误地请求帮助；拒绝后独立放置的三例仍请求帮助。后者在原协议中是合法的再次请求，但不完成物品，因此不能把“有效动作”与“成功动作”混为一谈。

[正式分阶段分析](../../results/language_v2/formal_analysis.json) 进一步显示：共享首步只完成 10/120，组合后的困难无法与首步基础失败分离。248 次无效动作中，111 次在不需要支撑时求助、48 次在伙伴离场时求助、48 次不符合当前负责人、41 次目的地错误。该分类描述可见行为，不推断模型内部动机。

本轮因此形成一个设计上的否定结果：**当前模型与接口组合未通过基础协议校准，其低分不能用作“局部强、组合弱”的证据。** 这不否定原始研究方向，但否定直接扩大这套题库并据此撰写主结论的路线。

下一步顺序：先在开发任务上校准明确的公开动作接口与可恢复反馈，再用新的冻结物理仿真任务检验持续活动。动作候选必须由公开事实和通用动作前提生成，不能利用隐藏有效约定筛出正确答案。额外求助优先计协调成本并给出真实反馈，不以一次无害请求直接跳过整项工作；失败、重复请求和资源冲突仍需可测。原 v2 结果和提示原样保留，后续版本不能覆盖它们，新的分数也不能包装成同一冻结测试的无偏提升。
