# 联合推理与真实共同用餐

[完整报告与运行时Sim视频](index.html)。[预设运行协议](PLAN.md)。本轮聚焦能自主推进、调整活动的生成式人策略；完整成熟Benchmark与cobalance效度仍未完成。

## 为什么改变策略结构

过去分开生成长期意图和当前动作，出现自己的目标与实际操作对象不一致、反复操作第一物品等行为。本轮用Qwen3-14B一次完整推理同时产生个人意图、可变目标和一个当前动作。目标变化、对象顺序、等待与空间请求都由模型决定，没有外部目标变化时间表、评分路由或自动计划执行。

个人背景为共同用餐：希望食物接收餐具靠近自己、其他物品方便取用，依据机器人实际活动自行调整安排。参考[COOPERA官方人模拟说明](https://github.com/dannymcy/coopera_code/blob/main/HUMAN.md)的背景、环境与意图历史建模思想；没有下载其外部数据或宣称本地人模型通过了真人效度验证。

## 设置

init0／seed0、20Hz、60秒，一次世界和人初始化。人每2秒thinking推理，最大3072token；只有结束思考后的最终JSON执行，原始思考完整保留。前三场各30次人模型调用。自主资格场景前4秒通过真实控制泊车，随后机器人模型调用0，不计HRC成绩。

两共同活动采用真实π0.5-LIBERO，各120次推理、1200个原生7维OSC动作，无视觉协调器。语言输入为原任务加最新公开人消息，须与只有原任务语言的基线区分；人的私人目标不会路由给机器人。实际双相机像素、本体、动作、执行控制和物理时钟独立核查。

场景使用原生MuJoCo接触动力学；机器人无运动学吸附，人为双指受力代理与骨骼显示，物体pose写入0。人读理想几何，完整人体／五指、心理与跨人泛化未验证。推理时世界暂停，视频按模拟时间播放，不代表系统能在真实时间达到20Hz的模型推理速度。

## 执行问题与独立修补

前三场使用冻结的原始请求处理。自主操作直接记录了两次旧place完成后的重启：17.65→17.70秒、55.55→55.60秒，没有新的神经回答，却从idle变为“物体不在手中”的failed。上一轮自主操作也有同类见证。这是执行器把缓存动作再次当成新请求的问题，不能把随后重复行为全部归因于模型权重。

修补为每次实际神经回答赋予请求身份：活动中的原语继续跟踪物品；完成或失败后，同一个缓存请求不会重新启动。新的神经回答仍能显式重试相同动作，没有自动选择第二物品或下一目标。独立回归使用真实原语的放置／释放后状态覆盖该错误；未来运行保存逐控制步请求记录，用原始模型回答与物理状态重建递送。

修补后的完整60秒自主操作复测使用相同场景、模型与背景，另存`joint_request_delivery_20261007`，不会回写前三场原始结果。该复测已完成：30次真实NN推理、1200控制步，321次终止状态的缓存请求没有再次启动，独立重建全部请求通过，原先的缓存place重启见证为0。碗16.40秒首次释放稳定到达、期末关系成立；人仍只操作碗，酒瓶无人接触，整体个人目标false、目标变化0、7次放置请求被拒绝。物理时钟、视频、真实反馈和运动资格通过，但多物品可靠推进依然没有实现。

## 结论边界

四场视频分别1281／1201／1201／1281帧，20fps、896×512，全部逐帧解码和时间轴核验通过。报告同步展示收到的上次意图、本次选择的意图、原始请求／参数校验、当次输入握持和视频帧的实际执行状态。文字解释、被接受的动作与物理成功分开。

本轮同时改变策略结构、推理模式与个人背景，且发现请求处理混杂，不能作单因子改善归因或算法排名。多物品可靠推进、实际人移动接收物、更广任务／初始状态、学习人策略与完整人体动力学仍待验证。后续重点是以真实成功动作范例进行神经动作学习和独立资格评测，以及标准输入协议下的实际动态条件，避免再用提示微版本或工程绿灯替代核心效果。

后续直接VLA入口已显式支持task_only（只用原任务语言）和public_speech（追加公开人消息，沿用默认），并在provenance与数据文件身份中区分语言接口、人背景、memory和请求递送。该新增配置未用于本批共同活动，不将代码可选项称为已经完成原生基线对照。
