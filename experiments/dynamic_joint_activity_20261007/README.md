# 动态共同活动：新Goal的实现起点

[统一报告入口](index.html) · [完整设计](DESIGN.md) · [首批开发协议](DEVELOPMENT_PROTOCOL.md)。新Goal仍在推进；本页不将开发入口或旧实验当作验收完成。

本次明确纠正：人类拟真关注需要、意图、参与和对机器人行为的响应。人抓放LoRA与高保真接触不再是研究主线。人的在线策略使用已有Qwen3-14B，无旧操作LoRA；连续运动学手和持物约束可靠表达其明确动作，机器人仍由实际π0.5输出7维原生OSC并物理执行。

已实现三活动语义及统一运行入口：准备点心（人提供碗、机器人装入、人接收）、整理饮品（人决定留用或收纳、机器人处理、人确认）、清理取用区（人准备空间、机器人开抽屉、人后续取放）。这些是依赖描述，后台没有任务顺序路由。完整活动成功判据仍需补齐，不能把原生单物体目标替代整体活动。

双方渠道已接入：实际人消息原样进入VLA prompt，实际动作进入其两路相机；机器人的测量和公开回复进入人下次输入。人的背景、需要、记忆和外部通知保持私有，只有人实际公开表达的内容可以进入机器人。直接VLA没有聊天输出，动作是其反馈；视觉协调系统身份单列，不能将其规划归因于裸VLA。

首批dev约10／16／14秒主动中断，因实际schema／动作拒绝而单列诊断，三段视频核查通过。schema目录三条完整80秒已完成，各人40次NN、机器人160块／1600动作，完整视频与连续执行核查通过。人主要取物后持有等待，抽屉有一次place早于实际握持而被拒绝，三场原生机器人目标均未完成。

编码检查进一步发现：schema点心156/160、饮品156/160、抽屉140/160调用超过π0.5真实200token上限。原始消息进入调用参数，不等于近期交流／末尾状态全部进入模型；本批必须单列输入诊断，不归为HRC能力。后续入口排除重复活动描述，保留最新两条完整公开表达；服务端对语言＋状态总长超限明确报错，并保存真实token／mask／解码输入，不静默截断。协调系统仍保持公开对话历史，作为单独系统评测，不隐藏增加裸VLA能力。

目前已通过233项有效回归测试，2项跳过；新增测试检查私有边界与机器人反馈确实改变人输入，以及人pick连续且不改机器人关节。测试仅证明对应功能，不能证明拟真人策略或活动效果。

数据按observation_XXXXXX.png、_wrist.png、_state.npy、_actions.npy同stem加载。JointActivityDataset从实际robot_control恢复执行标签；新的公开信息可以中断动作块，未执行动作不得当实际标签。没有配对manifest，失败行为不标专家成功数据。正式数据划分与导出尚待固定。
