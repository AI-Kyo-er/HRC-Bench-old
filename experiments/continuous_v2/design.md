# HRC-Continuous v2 实验设计

## 研究问题

本实验不把人类协作简化成一个固定状态机，而是测试机器人能否在同一项持续共同活动中保留、更新和重组交互关系。场景由 `ActivityContract` 生成：它声明活动目标、工作项、前置承诺、共享资源和可重规划触发条件；它不规定第几步必须出现哪个事件。

- **RQ1：** 机器人在孤立交互和长度匹配串接中表现良好时，能否处理具有跨片段依赖、嵌套或并发的结构？
- **RQ2：** 机器人能否根据当前可见行为以及既往公开结果，调整分工、回应求助和处理暂离/重返？
- **RQ3：** 复合结构的代价是否来自结构依赖，而不是仅仅来自物体数量、动作数量或 episode 时长？
- **RQ4：** 当机器人发生可见延迟或失败时，机器人能否主动求助、承认未完成并与伙伴重新协商，而不是继续执行失效计划？

## 条件与对照

每个结构条件使用相同的对象类别、动作协议和公开观测边界。布局、目标区域、分工、可用性和离返概率由种子生成，并在 episode 之间固定记录。

1. **isolated**：单一共同执行作用，用于确认基本动作和记录协议。
2. **matched_serial**：把指导和共同执行按长度匹配串联，作为“任务更长”的控制。
3. **compositional**：嵌套、并发或历史重解释，要求前一作用形成的公开约定影响后续决策。
4. **held_out**：训练中出现过相同的局部作用，但依赖关系或组合方式在测试中留出。

同一组场景可分别使用三种伙伴条件：

- `fixed_replay` 只按初始分工完成预定贡献；它不读取机器人行为，是传统回放对照。
- `reactive` 读取当前公开动作、占用和求助消息，只对当前可见事件做即时反应。
- `adaptive` 在公开观测范围内保留信任、工作负载、接受请求和离返历史，并据此重新分配贡献。

三种伙伴都运行在同一逐 tick 接口上。伙伴不会被脚本告知“第 N 步离开”或“第 N 步接管”：离返、让行、接管和重新承诺由当前几何、公开动作、公开消息、工作负载和冻结的概率参数共同决定。场景中的 `DynamicsSpec` 只给出动作延迟/失败概率、最大延迟和适应敏感度；延迟或失败在机器人启动动作时采样，随后以 `action_delayed`/`action_failed` 公共消息和事件进入闭环。

活动契约的前置条件只在贡献提交时检查。例如 `robot:blue:tray_blue` 可以声明依赖 `human:red:tray_red`；机器人可以提前尝试，但若公开完成记录尚未满足，后端会报告 `action_blocked`，保留物体未完成状态，等待双方基于新观测重新规划。这是约束驱动的执行，不是把“阻塞”编码成固定状态转移。

这里的“动态”有明确的运行时含义：`InteractionStructure` 和
`interaction_acts` 是用于生成、分层和分析数据的结构标签，`WorkItem` 的
前置条件是提交时的可验证约束；它们都不携带“第 N tick 执行 A，再执行 B”
的事件脚本。每一 tick，伙伴先根据公开消息、几何占用和当前承诺选出一个
动作，策略再从公开 `Observation` 产生动作块；动作块可以被新消息、让行、
失败或延迟打断。这样，同一个场景契约可以产生不同的轨迹，且轨迹差异来
自策略、伙伴反应、扰动和几何，而不是来自预写转移表。

伙伴模式不是对真人行为的心理学结论，而是用于拆分机器人能力边界的可复现机制条件。正式真人实验需要另行校准伙伴参数和伦理流程。

## 输入、输出与分析单位

模型每次接收一个公开观测，可以是 RGB 加结构化状态（VLA）或结构化/文本状态（WLA），输出一个 `Action`。模型不能读取 `scenario.json` 中的私有目标、伙伴信任、可用性或评测标签。一个 episode 是分析单位，逐 tick 记录用于重算协调和安全指标。

Genesis episode 还必须保存 `demo.mp4`、RGB 观测和 `trajectory.npz`。`index.html`
同时提供桌面轨迹动画和真实 Sim 视频入口：动画用于精确对齐公开事件，视频用于
核查 VC Avatar、Franka、物体和渲染画面。视频采用当前后端的物理与接触近似，不能
替代结构化指标，也不能把运动学 attachment 解释为真实夹持动力学。

对 Genesis，报告生成器会检查每个 episode 的 `demo.mp4` 存在且非空；缺少视频时
拒绝生成正式回放报告。`video_timeline.json` 是新运行的时间轴完整性检查，记录
`fps`、`frame_count` 和每帧的 benchmark 时间。旧运行没有时间轴时仍保留原视频，
但报告把它标为“无时间轴”，不伪造视频与轨迹的精确对应。参考 `ContinuousWorld`
不适用该视频门槛。

主要指标分为三类：

- **机器人结果：** robot success、完成时间、动作块数量、提前终止和动作打断。
- **伙伴响应：** help response latency、human correction、yield/away 反应、空闲比例、重新分工是否完成。
- **扰动与恢复：** robot failure、delay steps、human reassignment、recovery latency，以及失败后双方是否完成剩余贡献。
- **联合结果：** task success、proximity warnings、依赖结构对应的完成技能、协调代价。

`task_success` 与 `activity_success` 都根据活动工作项的终态计算，因此允许
在公开协商后由另一方接管。`robot_success` 和 `human_success` 表示对应目标
区域的终态是否满足；`robot_role_success` 与 `human_role_success` 则根据完成
技能的贡献者记录判断原始角色是否坚持完成。`coordination_cost` 只是当前参考评分，不能替代
HRIBench 的完整指标集。`blocked_transfers` 用于分析依赖约束带来的协调负担。
接入物理后端后，应加入碰撞、接触力、停机和恢复标签，并报告每个 seed 的
分布而非只报告一次运行的成功率。

伙伴的 `HumanAdaptiveState`（信任、可靠性信念、负载、承诺稳定性、主动性、
对机器人依赖、求助意愿和可用性）是评测器内部的潜变量。它由延迟、失败、
求助、空间冲突、暂离和重返等公开证据在线更新，并写入
`events.jsonl` 的 `human_state_update`；它不进入模型的 `Observation`，也不
直接路由机器人的动作。这样可以分析“机器人行为是否改变后续协作”，而不把
一个可修改的 status table 伪装成机器人记忆或任务状态机。

机器人策略的反事实比较固定同一场景实例、布局 seed、伙伴模式和初始潜变量，
只替换策略输出。`run_counterfactual_benchmark` 用稳定的
`<policy>/<scenario>` 目录和 `counterfactual_group` 字段配对，不使用关系
清单；因此可以直接把不同 VLA/WLA 的 `policy_io.jsonl` 与相同场景的公开
观测逐 episode 对齐。

## 历史反事实门槛实验

`history-counterfactual` 固定同一个场景、几何布局、伙伴初始状态和随机种子，
只替换机器人策略：`greedy_public` 直接承担可见贡献，`request_help_public`
在承担贡献前先公开请求伙伴接手。两条轨迹因此共享一段几何状态窗口，但可能
产生不同的失败、接管和后续伙伴行为。实验记录人类动作、公开消息、伙伴状态
更新以及对齐窗口，并计算 `same_geometry_steps`、
`history_conditioned_action_divergence` 和首次分化步。

旧反事实只匹配几何，没有匹配当前公开消息与占用。因此它核查失败 / 求助 /
接管链路，不能排除即时反馈，也不能独立证明持久历史机制。新的匹配探针见下节。

## 证据门槛

参考 `ContinuousWorld` 只能证明场景契约、公开边界、伙伴闭环和评测记录可运行。只有在相同场景实例上接入真实 VLA/WLA，并通过 Genesis/真实机器人验证接触动力学后，才能讨论模型比较。即使 held-out 条件更难，也需要与 matched_serial 的长度、动作数和几何难度配对，才能把差异归因于交互结构。

## 匹配当前输入的历史探针（2026-10-05）

问题：同一公开求助下，过去可靠 / 失败的机器人行为，是否通过伙伴持久判断
改变后续回应？实验先实际运行三个杯子的历史贡献，再从保存的公共观测逐 tick
重放伙伴学习。可靠条件更新成功贡献的 trust / reliability；失败条件依据三次
公开失败与接管更新判断。冻结条件执行同样协议，所有适应更新均关闭。

探针显式重建当前世界、消息上下文和其余内部变量，只带入 trust / reliability。
这是用来识别模拟机制的受控消融，不是自然无重置的持续 HRC。机器人首次执行
同一求助；人接受后等待人完成，拒绝后机器人自行执行。五项门槛是：首次模型
公共输入、首次 RGB、首次动作，以及回答前伙伴完整公共输入、回答前 RGB 哈希
都相同。仅匹配几何、仅匹配第一帧或只比较输入标签均不合格。

Genesis 三个 seed 中五项门槛全部一致。可靠适应伙伴接受，失败适应伙伴拒绝；
冻结伙伴在两种历史后均接受。这个结果证明所实现的伙伴变量影响行为，而不是
只写日志。它不证明更新公式是真人规律，也没有评测机器人识别伙伴变化的能力。
下一步必须保留同一世界与伙伴、不重置地跨贡献运行，并比较真正训练模型对
公开变化的处理；还需避免把当前消息差异误归因为隐藏历史。

## 原生 VLA 的操作控制与证据边界

`DroidVLAAdapter` 接入官方 π0.5-DROID。模型输入严格限制为真实外部与腕部 RGB、
7 个臂关节位置、夹爪状态与公开语言。N×8 动作块按官方 DROID 归一化关节速度
标度转换为关节位置目标：每 15 Hz 步乘 0.2 rad；夹爪 0 打开、1 闭合。
适配器不会借助物体坐标替模型选抓取目标，也不会替模型产生协商或求助动作。
公开任务更新会丢弃缓存动作块，并重新推理。

原生关节抓放只依据实际指间点到物体的距离与实际夹爪宽度，打开时在当前位置
释放；它仍使用运动学 attachment，不能声称接触动力学。公开几何 IK 教师先
确认该关节接口确实可以搬运，再用真实模型检查视觉到动作闭环。不能用教师
操作成功冒充 VLA 成功，也不能用一次跨分布任务失败推断没有 HRC 能力。

同步推理时当前模拟时钟暂停，模型耗时独立记录；尚未让真实推理延迟推进伙伴
行为。因此 15 Hz 是模拟控制频率，不是实时调度或延迟效应已验证的证据。

新运行的活动评分要求物体释放到区域、提交符合依赖与交接方向的贡献记录；
不能只凭几何终态成功。自定义 item_id 也按物体 / 区域匹配工作项；接管后继承
同一依赖。旧评分快照保持原样，不按新代码改写。
