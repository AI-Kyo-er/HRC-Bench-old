# 已选人贡献的连续执行契约

原抽屉技能库条件中，机器人5.6秒已真实打开，人44秒开始请求把奶酪放入，七次都因仍持餐盘被拒绝。错误来源是单手代理的资源占用，不能归为机器人HRC失败，也不能将人的请求当作已贡献。

新模式显式启用human-auto-buffer：仅当人已经选择relocate另一物品时，执行器先把原本由人持有的物品连续暂放到该物已有的公开个人缓冲区，再执行所选物品搬运。暂放不是NN选择新任务，不读评分，不选下一个活动，不操纵机器人持物；缺少公开缓冲位置或目标由机器人接触时仍拒绝。重复请求不重启当前宏动作，速度上限仍0.2m/s，机器人位姿写入0。

人知道执行契约，可以选择其他安排而不暂放；actor receipt记录自动暂放的原持物及区域。原失败按旧版本保留。新抽屉条件仍init2 / seed63 / busy / robot_request / 120秒、视觉Qwen3-VL-8B＋π0.5、九原生技能、人候选与反思。提示说明与执行契约一起变化，不计算严格单因素提升。

先检查所选贡献是否实际兑现，再审阅参与变化、公开请求和共同活动。暂放引起的物体移动不自动计NN高层策略变化，也不因收纳完成就证明cobalance或机器人主动请求能力。
