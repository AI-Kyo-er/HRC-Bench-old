# 从动态生活情境推进到交互结构评测

依据项目[原始idea](../../.codex/mds/idea.md)第二区分的六种交互结构，以及本批实际输入、贡献中断和离返记录。这里明确后续任务设计，尚未实现或运行；正式样本仍为0。

## 两个任务维度

加入、离返、用途改变、偏离、纠正和求助描述生活中出现的变化。接力、嵌套、并发、历史赋义、双向诱发和离返连续性描述这些变化怎样影响同一共同活动。正式条件需要记录两个维度及实际证据；不能只做六种通知，再把它们当成原idea的完整结构覆盖。

当前候选72条是三活动×六情境×两初始化×两系统的未冻结矩阵，没有交互结构或匹配串接因子。继续将它原样扩大，不能回答“局部能力能否组合”的问题。它保留作开发候选，不作为已经批准的正式设计。

## 用当前三活动构造结构

| 结构 | 日常活动及交互依赖 | 需要实际证明什么 |
|---|---|---|
| 接力式转换 | 人说明哪些饮品留用、哪些可收纳，随后提供瓶子并参与整理；提供过程不能覆盖原用途信息 | 提供后仍按有效约定处理，或双方公开更新约定。不能把“我提供”理解成已完成或给Robot的隐式指派 |
| 局部嵌套 | 整理过程中，人根据新取用需要纠正当前酒瓶安排、临时接管或保留瓶子，然后交还仍需要的贡献 | 纠正只改变相关需要；已经清理的部分保留。双方确有接管／交还，不能只由人另做一遍全部活动 |
| 同时叠加 | 人清理个人盘子，同时说明酒瓶用途；其实际手部运动占用Robot操作区，形成信息、互补贡献和共享空间约束 | 三种作用确实在时间上重叠，Robot获得公开线索并据当前资源协调。若只有一个主体动作，不能认证同时执行；不要求高保真人体接触 |
| 历史赋义 | 同样的取瓶／保留动作，分别发生在已接受的接管约定、已公开的用途纠正或个人取用约定之后 | 对同一可观察动作的响应受有效公开历史影响。历史必须曾进入模型输入，不要求猜私有心理；不能把新目标名称当历史依赖 |
| 双向诱发 | Robot自主发现用途不清或资源不方便，提出具体请求；人依据负担接受、改提案或拒绝 | 真实Robot请求、人不同回应及后续组织变化。参考可展示请求链的可执行性，正式条件不由环境生成Robot请求 |
| 离返连续性 | 人在抽屉存取或点心准备尚有贡献时离开，Robot推进可独立贡献或说明受阻，人回来后衔接 | 一世界内保留进度、未履行贡献和约定，身体或操作参与确有改变。合理取消允许保留，不强迫返回或强迫继续 |

以上是可协商的活动依赖。运行时不按结构标签路由人或Robot的下一动作；结构标签只进入研究者的条件记录和事后分析。人仍可坚持、改需要、拒绝、保持参与或提前结束，未出现预期结构的样本保留。

饮品新布局上架的两条参考失败已保留。涉及上架的设计需先补足相关初始化和状态下的实际操作资格，不能用这些尚未合格的操作条件证明交互结构更难。并发场景同样需要证明人执行能可靠表达所选贡献、Robot可获取必要线索；零夹爪接触不等于全身安全。

## 三层比较及匹配口径

1. **局部条件**：分别测试公开用途理解、资源提供／接收、纠正或暂离处理。保留同样物品、允许的操作和实际模型接口，记录基本操作是否可行。
2. **简单串接条件**：把相应局部贡献放到同一活动中，但取消跨片段的约定依赖和并发。匹配所需基本操作、信息量与观察窗口；不凭相同120秒长度就称难度匹配。
3. **依赖或并发的复合条件**：保留同一操作范围，使前一约定影响后续动作含义，或使两个有效要求同时成立。不得额外增加只有该组才有的抓取难度、目标不可达或信息缺失。

生成式人有不同闭环响应，不强制三层共享同一动作轨迹或实际动作次数。运行前匹配的是背景、初始状态、可执行贡献和外部事实分布；运行后另报实际持续时间、操作暴露、信息线索、伙伴有效性及未发生结构。若匹配失败，保留并说明，不能偷偷筛掉不利样本。

历史对照可使用明确标注的前缀生成参考，并复制同一真实物理状态保留不同公开历史，再由实际被测系统运行后续。此前固定前缀与正式后段分开标来源；精确状态、控制来源和模型输入须核对。没有状态匹配证据，只能称背景对照。给出当前完整指令的辅助条件单列，避免把缺少必要线索当作记忆能力失败。

## 未见结构与评价

开发／适配与测试按交互依赖或嵌套关系划分。基础物品、操作和各局部交互可在两侧出现；保留新的关系结构，不能只换随机种子或目标名字就叫未见组合。正式冻结须列训练／开发接触范围、测试结构、模型版本、样本分配及人工审阅口径。

评价沿用可重建的共同成果、公开线索进入输入、有效约定的保留／撤回、真实贡献、离返衔接、过时等待和重复说明。结构暴露不足、伙伴误记事实、接口／执行失效、Robot操作失败和协调失败分别报告。不能因为当前首例出现提前自报完成，就先预设复合结构必然更差；也不能将两系统均失败直接归为cobalance缺口。

## 推进次序

收齐当前同版六例并审阅伙伴、真实行为和操作资格；完成至少一条有效的持续共同活动后，落实可执行的结构与对应局部／串接控制；再冻结两个实际不同系统、多初始化／种子的正式条件。所有重要运行保留完整Sim视频与失败，不以新设计文档或测试通过代替这些阶段。
