# 六情境开发批：完整结果与下一步决定

六条均为120模拟秒、一次世界初始化、同版生成式人、理想几何／接触协调＋实际π0.5。共202次人推理（101次需要＋101次贡献）、180次协调、464次真实VLA、14400步控制、14406帧完整视频。三次执行拒绝均来自第五例的真实Robot指接触。全部输入／执行／调用调度／视频核查通过；这不是可信伙伴、六情境覆盖或正式成绩的认证。

| 条件 | 已发生的行为与成果 | 尚未证明或存在的问题 |
|---|---|---|
| 点心用途变化 | 通知后实际碗放盘并释放 | 通知给出具体方案；食品未入碗，交付位置误认，Robot后来错误认可完成 |
| 饮品求助 | 身体离返、返回后用途讨论、Robot转上架、人接受 | 上架未完成，清盘被中断而误记；公开等待确认存在，没有明确的新协助／分工工作链 |
| 抽屉离返 | Robot开门，人清盘并存奶酪，初始存储结果稳定 | 无身体离返；早报完成、错技能、完成后过时确认。不能将正常任务结束冒充动态衔接 |
| 点心偏离 | 饮品通知引起实际搬瓶和载盘暂放，取消后公开改变需要 | 没有有效恢复点心；食品在个人区盘上、酒瓶与碗共点，单坐标区域限制了并排摆放表达 |
| 饮品纠正 | 人先自行纠错，新即用需要公开，Robot换操作，人实际搬瓶至柜顶 | 当前瓶子需要有成果，但不是Robot完成搬运；接管／交还约定不清、三次接触阻塞及盘位置变化 |
| 抽屉加入 | 人从开场参与，Robot开门后人存奶酪，终态有底面支撑 | 没有中途加入；部分收回的门使原生开门分数失效，但不能以此否认已存物。Robot新增错误容器步骤 |

46项案例解释的记录锚点、16个过程区间已核对。解释仍由助手作出，没有真人效度或独立专家一致性。相同活动中确有不同选择和对伙伴的实际反馈，不能把这批全称为两个完全独立的代理；也不能由对话、最终同意或某个原生目标判断完整动态协作。

## 当前缺口如何影响正式评测

动态变化已有物理证据：用途相关摆放、实际离返、搬饮品的偏离、纠正后的自选搬运。中途加入、明确主动协助及多种人的回应、完整接管交还和有效持续重组仍未验收。没有变化的条件保留在分母，不用定时脚本强迫它出现。

人的动作层已经能连续执行主要贡献，但三次接触阻塞与同坐标多物品摆放要单列。接受／完整宏结束不保证最终摆放语义正确。人的事实记忆和Robot的自愿声明解释、技能选择、过时确认仍不可靠。直接扩大未冻结72候选会混入伙伴／接口失效，无法归因先进模型的动态协作能力。

当前系统的协调能力来自额外Qwen模块，原生π0.5收到短操作并输出7D动作。不能将模块的纠错和话语归给裸VLA，也不能将模块选错技能归为VLA不服从正确指令。裸VLA的长公开输入还有200token容量限制，已有独立CPU证据；未经适配不计协作失败。

## 下一项系统改动

同时处理两个有直接证据的缺口：让简化人执行能表达同一区域内的合理多物品放置；让人策略获得与自己所选贡献相连、区分进行／中断／实际结果的事实反馈。它们用于表达和感知，不由后台替人或Robot选择下一个策略。不再只调某句提示，也不围绕单一酒瓶位置继续试变体。

新方法必须在三活动完整链路重新验证，保存失败及真实视频；只有需要得到支持才考虑更强生成模型或训练。任务还应落实[交互结构、匹配串接和未见组合](COMPOSITION_DESIGN.md)，不能以六个生活通知代替原idea。正式两系统、多初始化／种子比较仍待资格和运行前冻结，正式样本为0。

所有六条原始结果保留，重要视频不裁剪。批次终态后已停止自有空闲π服务并核对四卡显存释放；没有停止他人进程。大文件保持data1及仓库软链，数据是开发行为记录，不是成功专家标签。
