## 四类真实操作

|案例|原生任务|操作/交互重点|人私有偏好取用对象|
|---|---|---|---|
|food_into_bowl|libero_goal task6，奶酪包放入黑碗|包装物/容器，接收容器可被人移动|黑碗、酒瓶|

这些偏好只进入人模型，不是固定人动作、分配清单或变化时刻。模型可以保持、改变或放弃自己的目标，
可以选择其他合法物品、提出公开协商或等待。机器人只读自己的任务、真实图像/本体以及人公开说出的消息。
本轮没有把人私有目标、偏好名单或评测成绩注入机器人。

场景库存从当前原生环境获取：可移动物品、固定柜/炉/架以及它们的实际坐标/关节。
人的grasp/push接口只允许可移动物品，固定fixture需要模型通过公开提案协调，不能当作手可自由抓走的物体。
目标实体与接收区域直接从原生goal/site-parent解析，不凭字符串猜测；没有cookie也可以运行。
个人home/personal区域由初始化库存生成，位置之后不变，不把物体或人体瞬移到目标。

## 原生完成与人的完成

原生奶酪“入碗”任务编码为On关系；保持它的原定义，再加入物体实际接收容器接触、双手释放、稳定0.2秒。
酒架/炉面目标是指定site，解析到其真实parent body：既需原生指定区域成立，也需实际支撑接触/释放稳定。
新多主体任务的物体释放检查同时排除机械臂与人手接触，不把“机器人松手、人仍夹着”认成放置完成。
抽屉按原生Open条件、对应关节实际变化>0.02m及速度低于0.08m/s稳定0.2秒，不能套用放置释放分数。
人的个人区域目标也要求桌面支撑与松开手、稳定；位置接近不能替代放下物品。
这些测量只事后评分，不负责选择双方下一动作。

## 模型与控制

真实π0.5读外/腕相机、8维本体和公开语言，原生7维OSC动作、最多10步块；Qwen3-14B每2秒生成个人目标与下一动作。
人使用上一阶段的真实双指接触手，XYZ/yaw/双指实际受力与摩擦，支持push/grasp/place/release及观察离返。
人物仍为完整VICO皮肤和骨骼的运动学显示，不代表完整身体动力学、五指手或真人策略效度。
人的几何/关节感知是模拟器理想读数，机器人仍用实际相机，不能把人解释为纯视觉策略。
四场景各40秒/20Hz、init0/seed0、independent倾向/episode记忆；世界/人策略各初始化一次，目标变化不由时间脚本触发。
两台人+Sim分别GPU0/1、模型服务GPU3，各程序单卡，启动前NVML检查并按PCI匹配CUDA/EGL。
两组同时运行共享模型服务的随机采样状态，不作严格配对因果排名。推理时模拟时钟暂停。

## 当前发现的执行边界

前两条动态伙伴记录显示：奶酪场景人虽偏好碗/酒瓶，却选择帮助抓机器人要处理的奶酪包；
实际18.8s双指抬起后，将bowl_home固定区域当作“放入碗”的接口目标。固定区域的高度/语义不等于
相对活动容器的放置关系，这一低层适配混杂需披露，不能把结果单独归因为VLA的HRC能力。
炉面场景人的盘抓取未形成双指抬起，泛化抓手在薄盘上的操作前提尚不足。
这些能力边界与任务/角色解释分别记录，后续需相对容器工具与各类物品的操作校准，不能仅继续改同一句提示。
